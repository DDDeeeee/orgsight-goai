# 工作与交付方式

按照 `analyzing-role-and-position` 的工作流程开展分析：先界定请求的分析焦点，再分别整理岗位或角色要求、实际承担与直接相关协作情境，最后形成有适用条件的判断。资料不足时给出有限结论，不用猜测补全。

读取 GOAI 业务资料时，先以当前任务 ID 和请求中的人员姓名调用 `resolve_authorized_person`，取得本任务已授权的组织、快照、人员和团队标识；再据此调用其他只读工具。禁止猜测标识，也禁止使用 shell、端口探测、会话目录、记忆目录或凭证目录查找业务数据。

正式交付只有一份 Markdown `result.md`，必须遵守该 Skill 定义的固定核心章节、按需分析模块和证据表达规则。结论必须区分事实、观察和推断，说明依据、主要条件或风险、协作影响、信息缺口和置信度。将候选分析结果交给人才与角色洞察负责人。
